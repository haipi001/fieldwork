# UI-02：无效模型输出的已知用量结算

源码0.68.19/build97/schema28（没有新增DDL）。没有覆盖安装包、调用付费模型或访问研究目标。主DB只读观察仍schema26/runtime_calls0。

## 修复

此前模型响应的usage有效，但content JSON解析失败时，整个调用被标为unknown；会丢失已经获得的服务端用量。现先验证用量，再解析研究输出。

- OAI兼容与Ollama的输入/输出计数必须为非负64位整数，拒绝布尔、浮点、负数、超范围及缺失值；不能通过int()把无效计数转换成零/截断整数。
- 若用量有效、输出JSON无效/缺失/不是对象/含NaN，抛固定ModelOutputRejected，仅携带输入、输出计数及测量时长。不保留原响应或解析器异常上下文。
- 队伍与结构化Worker用原调用ID/决策/幂等键结算已知词元、配置费率费用与实际请求时长；不接受研究输出、不新增研究草稿/回执/正式Finding。
- 这类输出失败暂停，需人工检查后显式重试；同一tick或刷新不自动重复调用。
- 结算存储失败时保留unknown额度，记录固定错误类型；不把未提交事务伪称settled。
- Task API批量从不可变模型账本读取已知词元/费用/时长，失败任务也显示已知用量；UI中英区分“用量未知，预算仍保留”与“输出JSON无效；已知用量已结算”。

- 解析单测覆盖缺用量、布尔、浮点、负数、超大整数以及截断/数组/null/NaN输出；拒绝输出异常不含私有标记或原解析器上下文。

## 回滚与限制

没有新迁移，回滚此增量保持schema28即可；保留已提交用量/时长，不删除unknown。源码降级到更早schema版本仍需匹配对应数据库备份，不能丢弃新增调用证据。
服务商报告用量不等于账单，费用仍使用配置费率估算。真正断线/缺用量/进程死亡的unknown仍未取得凭证化核对UI与自动安全恢复；未知调用不释放额度或重发。云精确输入、实际本机计数、故障回退、Runner存活、原生及完整发现/独立确认/三域质量/规模/发布继续保持未完成。
