## 结论

在明确授权、限定漏洞类型、证据可重放和安全执行环境的前提下，自动分诊、受控复验及独立确认在现有架构上可行。已有持久化任务、证据、Scope/Policy、预算、HTTP 两轮对照和有限 V5 Oracle，可以逐段连接，无需重写产品。

这不是“自动发现任意漏洞”的可行性保证。真实工具与模型驱动发现的质量、通用独立判定、跨进程恢复，以及 Traditional/Web3/Agent Security 三域完整覆盖尚未通过产品验收。不给没有统一验收分母的完成百分比。

## 本次 UI 操作逻辑

复验页顶部增加“先分诊，再复验”。用户选择一次运行，显式读取当前分诊，默认看需要处理的项；可切换全部查看普通观察/重复记录。分页计数只代表已加载批次，不冒充全库统计。显示缺证据、缺身份、缺绑定或专用验证器等阻塞原因。

分诊读取仍是只读预览；适用的 HTTP 候选可进一步检查计划、明确确认后启动单条受控复验。打开页面、查看计划、切换语言或主题不会启动请求。材料就绪、授权允许、行为复现、漏洞确认是四个不同状态。原有候选详情、证据和回执轨迹继续保留。

### P0：单条真实核心闭环（最高优先级）

1. 冻结本地 HTTP 对象权限靶场：漏洞正例、修复负例、合法共享反例；明确支持范围和预期结果。
2. 使用实际发现链获取证据，不预置答案或候选来替代发现；记录工具/模型版本、输入、成本和产物哈希。
3. 接通 V5 分诊后的准备、授权确认、受控执行、取消、进度和阻塞处理。身份和预算不足时不执行。
4. 独立执行器从证据重建最小复现与负对照；完成当前 Scope/输入核验、回执及正式结果晋升。`reproduced` 不能直接等同 `verified`。
5. 三次清洁启动重复闭环；正例稳定复现，修复/共享反例不得误晋升。报告样本数与失败原因，而不是只报单元测试通过数。

### P1：持久可靠运行

- 持久租约、心跳、超时、去重和幂等；崩溃、取消、预算耗尽、输入变化时安全停止并保留材料。
- 独立后台生命周期；退出窗口后是否继续运行由明确配置控制。
- 监控窗口到调查/复验的连接；异常不直接晋升为漏洞。仅对可行动结果告警。
- 备份校验、干净环境恢复、升级回滚演练；完整依赖与钥匙串边界说明。

### P2：逐类型扩展与降噪

- 跨运行候选聚类、证据继承及失效规则；可逆归档，不删除原始证据。
- 为源码/依赖/配置、Web3 属性、Agent 权限边界分别建立专用验证器及正反例集合。
- 覆盖不足明确显示，不用模型推断填充完成度。包版本适用性不是可利用性结论。

### P3：发布级产品收敛

- 报告完整性、敏感字段脱敏、根因与实际影响、修复复测。
- 完整安装版 E2E、性能与长时稳定性、安全审查、用户可操作性验收。
