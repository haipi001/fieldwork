# 研究主线操作简化

用户反馈：整个产品操作步骤太多，下一步衔接不流畅。

## 本轮落地

- 创建项目后直接进入授权核对；确认授权后直接进入执行预检，取消中间返回详情抽屉、首页再找按钮的两次操作。
- 未授权项目点击执行入口直接接入授权核对，避免仅弹提示后让用户自行寻找入口。
- 修改执行参数后自动重新预检；输入期间立即清除旧预检及确认，拒绝过期响应，提交时再次比对参数。实际启动仍需明确确认并通过后端检查。
- 启动后定位当前 Run，并重置队列筛选，避免新任务被之前的筛选隐藏。
- 首页根据当前项目状态呈现一个主要下一步：授权、执行预检、当前运行、暂停处理、阻塞原因、独立复验、报告、证据。数据失败提供重试入口。
- 复验带入候选，报告带入确认发现，证据带入 Run；不将其他项目记录混入下一步。
- 首页收到终态运行事件后自动刷新结果；窄屏下一步区域排在图谱前。
- 保留全部 18 页面、原有高级功能与授权/执行/验证边界。

## 验证

- `scripts/check_v5_frontend_ui.py`：18 页面 × 6 宽度 × 2 主题 = 216 布局检查通过，以及创建/授权/预检/启动、任务控制、发现详情/报告等隔离交互通过。
- `scripts/check_v5_flow_ui.py`：连续主线、8 种下一步状态及跨项目运行隔离通过。检查参数变更取消已确认状态、迟到预检不能重新开放启动。
- 400px 实际浏览器检查下一步在图谱之前。
- JavaScript 语法、Python 编译和改动空白检查通过。
- 所有浏览器 API 使用隔离夹具，不启动扫描、模型调用或写入真实项目。

## 边界与后续

这是研究主线的简化，不能代表全产品操作改造完成。本轮未安装、重启或验收已安装原生 App；未提交或推送 Git。安全监控、研究组、模型配置、扩展和维护流程仍需逐个按以下规则收敛：

1. 每个状态有明确主操作，完成后带着当前对象进入下一步。
2. 自动完成只读检查和上下文传递，避免重复选择对象。
3. 常用路径优先，高级选项按需展开，保留全部能力和页面。
4. 失败就地说明可恢复动作，不让用户靠切页寻找原因。
5. 真实执行、外发、授权和验证保持明确边界。
