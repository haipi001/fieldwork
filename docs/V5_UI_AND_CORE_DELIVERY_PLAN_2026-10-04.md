## 跨包规则

1. 一轮只做一包，最多合并两个直接依赖包。每包列变更、迁移、测试、原生 App 操作验收、回滚、阻塞和下一包。
2. UI 先读取真实后端状态，再开放可执行操作；不以演示数字、Run 数或 Runner 数冒充 Agent 数。
3. 区分研究组数量、逻辑 AgentTask 数、同时租约数、Runner 并发数和模型调用数。
4. 配置变更版本化并绑定 Scope、Policy、预算和 Run；旧回执不能被新配置悄悄改写或晋升。
5. 页面浏览、预览、语言/主题切换不发目标请求。执行逐步核对当前授权、身份和预算。
6. 中英、明暗、宽窄窗口、空态、失败、取消、刷新、重启及原生安装版均需验收。
7. 原完整规划的 15 Task 和 8 类 Known Gaps 保持在范围内；一个功能的局部通过不能代表整体目标完成。

1. UI-00 至 UI-02：用户能真实配置队伍和模型路线，看到任务、预算与路由状态。
