# V5-ORCH-03 持久演化、租约恢复与容量边界

版本：Fieldwork 0.62.0 / Build 71 / Schema 24。

## 本轮证据与实现

新增反例在修复前实际复现五项失败：本地 Worker 绕过组并发与费用限制；旧租约结果在同一 Runner 重领任务后仍可提交；旧请求的失败清理可把新租约改为失败；进程崩溃且新进程在旧租约到期前启动时，后续本地 tick 不回收任务。另一个边界反例证明保留 16 个父代会调度 31 个新提案，下一代超出 32 个候选上限。

修复后，本地 Worker 领取前使用与通用 Scheduler 相同的组状态、并发与费用检查；每次显式 tick 先运行既有过期租约恢复，仍然尊重有效租约。结构化 Worker 和 Evolver 结果新增 `lease_attempt` 字段：首轮允许旧合同省略，重试后的结果必须携带领取时返回的 `attempt`；不匹配或缺失会在同一事务的任何图谱/用量写入前拒绝。本地 Worker 自动携带该字段，失败清理也核对 attempt，防止迟到响应改变新租约。

Evolution 页面允许对运行中任务发起“运行或恢复”，服务端决定租约是否过期。Advance 为保留父代预留候选容量，先安排全部 mutation，再按父代排名安排能容纳的 combine；返回 `omitted_combinations` 并在页面说明未创建数量。保留 12 或 16 个父代均可汇集到 32 个候选以内。历史版本已经建立的超量批次保留原记录，Collect 明确返回 409 并要求显式重新播种，不自动丢弃提案或返回服务器异常。

## 验证范围

`tests/test_v5_evolution_recovery.py` 使用独立 Python 进程和临时 SQLite 库，模拟在租约提交后 `os._exit(17)`：新进程在到期前不抢占，到期后可恢复；两次进程丢失会耗尽重试并保持失败，不生成草案。另有六轮演化每轮使用新进程，检验持久谱系、重复 Advance/Collect 幂等和 18 个任务的组预算原子截止。模型输出使用确定性测试替身，该测试不证明真实模型质量或真实 Provider 长时稳定性。

同轮验证覆盖其他 Runner 占据组并发额度、旧请求迟到成功/失败、Critic 重试提交，以及最大选择数量。浏览器网络桩确认运行中队列仍可到达恢复入口。最终测试及构建数字在本轮收尾追加。

## 变更、迁移与回滚

变更集中于 `v5_workers.py`、`v5_orchestration.py`、`v5_evolution.py`、`static/v5-evolution.js`，以及对应后端/浏览器测试、版本和规划记录。Schema 24 不变，无数据迁移。外部结构化 Runner 需在重试结果中回传 `lease_attempt`，可以直接采用 Lease API 的 `task.attempt`。未安装 App、触及真实外部目标或写入正式数据库。

回滚可以恢复上一版代码与 UI；持久记录继续可读，但会重新暴露本轮修复的租约竞争、预算绕过与容量问题，因此不建议只回滚 attempt 校验。无需恢复数据库或删除任务。未进行吞吐基准，不能据此声称 Scale 验收完成。

下一任务仍为 V5-ORCH-03 的真实 Provider 长时运行与更长代际压力验收；V5-SCALE-01、通用/远端可信 Verifier 和规划中的其他未完成事项继续保留。
