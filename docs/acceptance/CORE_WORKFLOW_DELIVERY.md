# 核心功能优先：端到端验收清单

用户要求：先把核心功能开发完整、流程跑通，不再优先扩充页面或候选数量。

## 核心能力与完成条件

| 核心环节 | 已有基础 | 必须完成的验收 |
| --- | --- | --- |
| 授权与预算 | Scope/Policy、身份、预算、取消门禁 | 授权变化、预算耗尽、凭证过期时停止实际执行 |
| 发现与证据 | 工具链、观测、证据和原始产物 | 真实工具发现正例；阴性/修复/相似反例不制造漏洞 |
| 分诊与准入 | 分类规则、材料整理 | 普通观察、缺证据、重复、待专用验证分流，保留来源 |
| 受控复验调度 | Guided 批次、续跑、HTTP 对照 | 合格项自动推进，不合格项可解释阻塞，恢复不重复执行 |
| 独立判定 | HTTP 两轮对照、V5 有限 Oracle | 隔离重放、当前证据/Scope 绑定、实际影响、反证；不能将 reproduced 当 verified |
| 结果与持续运行 | Finding 生命周期、报告、增量监控 | 修复复测、结果可追溯、重启恢复；独立常驻尚未部署 |

## 本次实现

- `GET /api/v1/runs/{run_id}/candidate-workflow`：只读、分页的材料与分诊预览，不启动网络请求或任务。
- 分诊状态：observation、needs_evidence、duplicate、blocked、unsupported_verifier、verification_ready、impact_review。
- 现有 Guided worker 在执行前持久化分诊理由与计数，只派发 verification_ready。仍需要原有 execute_ready 授权；所有真实请求继续通过范围、身份及预算门禁。
- 去重仅限同一批次、同一运行、同一项目、完全相同声明与引用证据。不同运行及不同声明不自动合并，原始候选不删除、不改写成“无漏洞”。跨页聚类尚未实现。
- 缺少引用证据时，相关页面不能代替证据使候选通过调度门。
- 复验结果复用新增 input_digest，绑定候选、引用证据、观察内容及授权上下文；旧版缺少摘要的结果不再自动复用。

## 2026-10-04：真实 HTTP 传输验收增量

新增 `tests/test_guided_http_live.py`，4 个场景通过：私有对象越权、修复拒绝、公开共享、合法登录共享。使用真实本地 HTTP 服务、实际 request_once 和 DNS/私网检查；临时数据库隔离。测试身份供应及 Scope 决策仍为 fixture，候选直接构造，不能算真实自动发现或完整授权链验收。每例实际采集3次、复验10次，预算记账10次；所有场景正式 Finding 为0。合法登录共享仍可呈现 reproduced，证实 owner_id 与匿名拒绝不足以证明业务越权，必须补齐共享授权语义/实际影响及独立重放，不可直接自动晋升。未修改生产数据、未扫描外部目标；安装版仍0.68.1，本增量只增加测试与验收记录。
