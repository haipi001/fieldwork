# V5-SCALE-01：并发预算与调度基准

交付版本：0.66.0 / Build75 / Schema24（测量时工作区仍标记 0.65.0，随后仅更新版本元数据）。

## 修复

组费用门禁此前只看已结算费用，并发任务可重复占用余额。现在在领取写事务中计算已结算费用、运行中任务剩余最大费用与候选任务剩余最大费用之和，再决定是否允许领取。有费用上限的组拒绝没有显式 `max_cost_micros` 的任务；旧任务需要以明确预算建立新的任务，原幂等内容不能暗改。

通用任务重试结算以前覆盖前次 usage，现累计 token/cost/runtime，并按任务总预算判定。通用 completion、heartbeat、checkpoint 增加 `lease_attempt`：首轮兼容省略，重试必须匹配当前领取的 attempt。检查点检查与写入合并为同一写事务，旧尝试不可更新新租约或写入迟到检查点。

## 可重放基准

命令：`python3 scripts/benchmark_v5_scheduler.py --sizes 100 1000`。临时 SQLite、真实 API 调度路径、16 个并发请求线程、4 Runner × 2 槽、组并发 8。首批 4 个任务注入租约过期，由独立进程重新打开数据库并恢复，随后完成。预算选非整波大小，以检查接近上限时部分领取。

| 指标 | 100 任务 | 1000 任务 |
| --- | ---: | ---: |
| 创建秒数 | 0.294 | 3.099 |
| 执行秒数 | 4.827 | 38.329 |
| 完成 / 剩余排队 | 51 / 49 | 501 / 499 |
| 组并发峰值 / 上限 | 8 / 8 | 8 / 8 |
| Runner 并发峰值 / 上限 | 2 / 2 | 2 / 2 |
| 领取 p50 / p95 ms | 113.269 / 499.587 | 107.194 / 496.293 |
| 完成 p50 / p95 ms | 35.928 / 113.660 | 35.438 / 133.625 |
| 完成吞吐 / 秒 | 10.566 | 13.071 |
| 独立进程恢复 ms（含启动） | 313.234 | 314.971 |
| 恢复后成功任务 | 4 | 4 |
| 已记费用 / 预算（构造微单位） | 51 / 51 | 501 / 501 |
| input / output tokens（构造） | 663 / 357 | 6513 / 3507 |
| 单胶囊最大字节 | 166 | 166 |

费用到达门槛后不再领取，余额未被并发重复预留；没有重复成功任务。报告成本/token 是固定构造值，不是模型实际费用。请求使用进程内 HTTP 传输，SQLite 连接并发是真实的；该结果不代表网络分布式吞吐。测试替身胶囊不含全量对话，但不能据此证明所有生产胶囊的质量。

## 边界、回滚与后续

尚未解决外部执行器违反所声明上限、失联/取消前已经发生但未上报的费用。当前预留在租约失效或取消后释放；需要持久 attempt 级费用保留/结算和真实 Provider 对账才能宣称端到端硬预算。基准只恢复显式注入的过期记录，不等同真实模型/工具进程崩溃全链路。吞吐为本机一次测量，同期存在回归测试负载，不作生产 SLA。

变更：`v5_orchestration.py`、预算/尝试专项测试、独立基准脚本、版本与验收记录。无 Schema 迁移；回滚恢复上一代码与 App，数据库无需降级。调用方须更新重试写请求的 `lease_attempt`。已修复的预算缺口若回滚会恢复。

下一项 V5-SCALE-01：失联费用持久预留与 attempt 账本；并按新的产品验收门推进真实漏洞发现与独立确认。完整目标保持进行中。
