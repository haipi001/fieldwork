# AI Agent Audit：本机 AI 软件行为审查

产品范围是这台电脑上的 AI 软件、Agent 与它们派生的工具进程。
Fieldwork 内部事件只是一个可选来源，不能代表全机行为。

默认操作仍是自动发现 → 一键开始 → 后台记录 → 结束分析。
不要求填写软件名称、PID、日志目录或审计表单。

## 已实现的 macOS 采集

- 从 Applications 的应用元数据发现已知 AI 软件。
- 使用 ps 的 PID、PPID、UID 和 executable 发现运行进程，关联其子进程。
- 使用 lsof 的可见 TCP 快照记录已建立连接的远端主机和端口。
- 使用 lsof 记录 AI 进程当前打开的常规文件描述符与访问模式，仅采集路径元数据。
- 打开文件按描述符、路径和访问模式增量记录；可读/可写表示描述符能力，不能证明实际读写发生。
- 对持久化快照做增量比较，记录进程出现、消失和首次可见连接。
- 显示采集覆盖与错误，保留暂停、恢复、容量保护和后台运行。
- 以 PID 与进程启动标识区分进程实例；结构化保留父 PID、可执行文件和直接匹配/子进程关联方式。
- 网络完整可见时记录连接不再可见；部分可见或失败时保留旧基线，避免误报和重复记账。
- 时间线按软件与事件类型筛选，最近记录优先，每次展示 100 条，可展开更早记录。
- 采集异常暂停对应监控并显示原因，其他监控继续运行。
- 系统快照不读取命令参数或用户文件内容。应用日志适配器仅保留工具元数据，不保存输入、输出、对话正文或密钥。

## 自动工具日志采集（0.41.0）

- 自动发现本机 Codex 会话日志与 Claude Code 项目日志，无需填写路径。
- 首次采集从文件末尾建立基线，之后只读取新增 JSONL 记录；不导入历史对话。
- Codex 适配 response_item 的 function_call/custom_tool_call 与对应结果；Claude Code 适配 tool_use/tool_result。
- 保留工具名称、请求/结果阶段、日志时间与散列关联标识，MCP 名称只在明确的 mcp__ 前缀存在时识别。
- 原始日志必须在内存中解析，但输入参数、输出正文、提示词与聊天消息不进入数据库或证据材料。
- 应用日志的来源标为 agent_supplied，独立性与签名真实性均为 false。结果记录不证明系统副作用成功发生。
- 未关联结果保留 unknown 工具名称；不读取旧请求或猜测执行内容，不解析 exec 中嵌套的代码。
- 保存字节偏移，重启后增量读取；半行等待完成，轮转/截断重新识别，暂停恢复时重建末尾基线。
- 每轮最多读取 4 MB / 2000 条日志，最多跟踪 4096 个文件；达到预算后轮转到其他会话，避免繁忙会话饿死其他来源。积压、不可读取与覆盖缺口明确显示。
- 当前仅适配已观察到的上述日志结构，不代表所有软件版本、所有 MCP 调用或操作系统独立事件流。

快照只能证明采样时刻可见的状态。不能把出现误称为启动、消失误称为退出，
也不能保证捕获短暂活动。已建立的连接可能早于监控启动。
应用名称和父子关系是归因线索，不能证明某个操作一定由模型决定。
没有授权策略时，连接记录不会自动被判定为违规。

## 后续完整行为采集架构

1. 系统事件采集器：文件行为、执行与进程生命周期。正式采集器应直接使用
   Endpoint Security，申请 Apple entitlement 并取得用户系统授权；系统扩展提供额外完整性保护。
   本机预检发现 Apple eslogger 可用于事件流诊断，但其手册要求管理员和完整磁盘访问授权，
   并明确不具备正式应用所需的性能、结构稳定性及系统扩展完整性保护，不能冒充正式采集能力。
   也不能用普通后台进程或辅助功能授权冒充已具备这些能力。
2. 应用适配器：从软件实际暴露的审计接口采集工具调用与 MCP 调用，逐一
   声明支持的软件、版本与字段，不读取所有聊天日志推断行为。
3. 浏览器适配器：识别网页中的 AI 会话与操作，需要浏览器扩展明确接入。
4. 证据层：记录应用、PID、采集来源、时刻、覆盖情况和置信度；权限不足、
   缺失采集器与未识别软件持续显示为覆盖缺口。

真实文件读写尚未接入；工具/MCP 的应用日志属于部分覆盖。
0.42.0 增加 [浏览器采集器](browser-ai-collector.md) 与本机接收接口，需用户安装及授权后才启用，真实 Chrome 端到端验证尚待授权。
仍不等于对所有 AI 软件所有动作的完整监控。
