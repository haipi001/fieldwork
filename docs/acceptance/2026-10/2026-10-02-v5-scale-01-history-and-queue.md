# V5-SCALE-01：长代际读取与千任务队列首轮

版本：0.63.0 / Build 72 / Schema 24。

## 已复现问题与修复

1100 代有效谱系读取在旧实现中实际触发 `RecursionError`。Population 列表还会对每一项重新递归校验所有祖先，历史越长，重复查询越多。现用迭代遍历校验谱系，并在单次列表读取事务内缓存已校验的祖先状态；缓存不跨请求。详情和列表显式开始读事务，防止同页缓存混用不同数据库快照。缺失父代、循环、跨组或非递增代际关系失败关闭；输入变化仍使后续请求重新计算当前性。

队列旧实现最多查看前 100 个本地候选或 500 个通用候选；反例中 1000 条高优先级旧 Scope 任务会永久挡住后方有效任务。现按既有优先级索引顺序逐条检查，命中首个有效任务即关闭游标并领取；不把全队列一次加载为 Python 列表。Runner 容量、组预算/并发、Scope、路由和能力检查继续执行。此修复消除固定前缀导致的饥饿，但未宣称极端规模下扫描延迟恒定。

## 验证证据与范围

- `tests/test_v5_evolution_history.py` 用临时库构造 1100 代保留父代谱系：详情读取成功，返回 500 代的列表全部重新确认当前性，SQL 调用少于 `1100 × 16`；下一请求可观察到输入修改导致的失效。循环损坏记录返回非当前状态。
- `tests/test_v5_queue_scale.py` 在 1000 条旧 Scope 高优先级任务后放入 3 条有效任务。本地和通用领取路径均能找到后方任务；旧任务 attempt 保持零，Runner 并发为 1 时第二次领取被拒绝。
- 40 项相关专项通过。上述数据由测试构造，不涉及真实目标、模型调用或 1100 轮实际模型演化；历史与任务数量测试不等同完整负载基准。

性能变化的可验证范围：旧版在长谱系报递归错误、队列错误返回无任务；新版完成读取与领取，并通过单请求 SQL 数量的线性上限断言。尚无吞吐、p95 延迟或真实模型成本基准。
