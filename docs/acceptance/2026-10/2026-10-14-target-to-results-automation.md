# 目标到实际结果的自动化

用户原话：不要让我填这么多东西，能自动化的地方就自动化。能自动获取的就自动获取。我接入AI是干啥的，就是帮我把这些东西处理好，让我看到最终的实际结果呀。

本轮后续用户指令：继续。

## 入口与执行

新建研究默认只显示目标，其他项目名称、领域、授权补充说明、预算及时限保留在可选高级设置。后端从规范化目标生成名称，识别网站、合约地址/浏览器 URL，以及已提供目录中的 Foundry/Hardhat 清单；高级设置的明确领域选择保留。默认授权仍限目标范围的读取、分析与既有保守预算。

新增只读 assisted-plan：从已有 Profile 和本机 Provider 快照匹配满足现有健康、回环地址、凭据与配置哈希约束的模型，并复用已提供的本地源码路径。只读准备不确认 Scope，不安装工具，不调用模型，不主动连接云服务。可用本机模型在支持的 URL/host 研究路径默认接入原有 native discovery 流程和模型调用账本。

新建传统目标的授权核对同时展示自动准备的实际工具、模型及预算。用户明确确认授权和执行后，系统自动核对最新计划并启动，不再要求重新选择模型编号或填写执行参数。启动接口检查计划摘要，绑定 Scope、Policy、参数、工具、预算、限制与缺项；计划变化或模型失效拒绝旧计划。有真正缺项时接入已有补充流程，不能把完全没有执行能力的运行包装成成功。

模型快照匹配不等于实时连通证明；实际模型调用继续由原有传输、预算、用量结算、私有上下文本机限制和验证门处理。源码/Web3/CIDR 等路径并不因自动匹配而获得新的原生网页 AI 能力。

## 研究组与报告

研究组自动带入当前目标和已匹配本机模型，角色默认一名研究员、并发一，预算/词元/时限受所选 Profile 上限限制。技术参数折叠但保留。用户确认“创建并开始 AI 分析”后，沿原有原子创建/预览摘要/幂等机制入队，并调用既有研究执行器；无模型时明确只排队。启动后的结果由只读轮询自动更新，不要求手动刷新；编辑表单、隐藏页面或操作期间暂停轮询。未知用量与失败不自动重发模型请求，输出保持未验证草稿。

首页报告入口选好已确认发现并自动编译预览。历史证明包缺失时仍阻止材料包导出，未自动提交报告。

## 实际结果

运行终态事件自动更新当前项目。首页直接显示所选 Run 的确认发现、待验证线索、实际证据数量、执行完成与未完成项，并自动读取既有完整运行总结。结果通过 Run 过滤的 Findings API 与 summary-report 取得，不能把其他运行或项目的历史发现算到本次。项目总览指标仍单独保留。

确认发现、候选、失败、未测试和没有证据是不同状态。AI 输出不会自动成为 Verified，未知业务权限与缺少身份仍不能凭模型推测补齐。
