# 第18节第一批：自动材料整理与五步准备流程

版本：0.33.0 build 34，Schema 12。状态：开发及验收中；本节底部记录最终测试与安装结果。

## 已实现

- 候选队列和单条候选可一键启动自动整理，不要求输入分诊理由或技术参数。
- 五步真实状态：准备、页面/源码整理、补齐候选、验证准备、汇总结果。没有伪造进度百分比。
- 基于当前运行的关联证据、同目标观察和已记录 GET 响应，整理标题、目标、已观察行为、原有假设、适用方法和待执行步骤，保留来源 ID。原候选、证据和用户编辑不覆盖；影响、金额、根因与严重度无证据则不自动填为事实。
- 从已有 HTTP 响应摘要提取同源链接、脚本引用和表单 action，去除查询参数和 URL 身份凭据，不访问或提交这些入口；结果明确为 discovered_only。
- 结果存入 guided_research_jobs；同输入重复请求复用结果，新材料产生新版本；每运行最多一个活动任务，全局最多四个。停止保留已保存材料，启动时将未完成任务标记为中断，用户可重试。
- 新的“开始挖掘”执行在完成后衔接本地自动整理（浏览器保存该轮跟进意图）；历史项目通过“自动处理候选”主动开始。现有授权与启动计划确认仍保留。
- 默认隐藏筛选细项、手工分诊、HTTP JSON 与专家配置；候选详情前置系统材料和具体缺口。账号缺口提供现有测试账号入口。

这一批落实18.6的状态/持久化及材料整理/UI基础，尚未完成整个M2。

- 自动整理不发新目标请求，不执行新的独立复验；候选结果仍为待验证，验证准备步骤显示待继续。
- HTTP身份端点/对象字段自动语义绑定、登录向导简化和登录后自动续验尚未接通。现有测试账号工作台仍有专家字段。
- 受控页面补充采集、跨轮覆盖缺口调度和隔离Web3复测仍待做，不能把“继续整理”说成新一轮实际扫描。
- 重启后重新整理来源快照，不是完整的逐步骤执行断点续跑；已完成快照可恢复阅读。关闭浏览器后自动跟进需重新打开页面，不是服务端永久调度。
