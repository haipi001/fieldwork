# UI-02：累计模型时长与在途Provider变更

## 实现范围

源码0.68.17/build95/global schema27/V5 schema7。没有覆盖安装包；生产主数据库本轮只读观察仍schema26、runtime_call_timings不存在。实际原生验收使用隔离临时数据目录，已迁移27且保留原8调用，不是生产迁移。

### 累计时长

- 新增runtime_call_timings，每调用只有一条不可变时长与历史时长基线，插入必须对应settled调用；更新/删除由SQL阻断。
- UsageReport新增可选runtime_ms；结算用量、状态、时长在同一事务内完成，重复报告不重复记录，不同报告复用幂等键拒绝。旧报告不带runtime字段时保留原摘要计算。
- 内置结构化Worker和队伍Worker提交监督器测量的模型请求时长，语义验证失败仍保留调用的词元、费用和时长。
- 下一尝试预算=min(Profile每次上限,任务累计预算-历史时长)。无时长的既有调用按原预留时长上限保留，未知调用不自动重试。历史agent_task_usage的时长基线不能因新的调用记录被清零。
- 任务读取批量聚合已记录累计时长和未确认时长；队伍表单明确“每任务累计模型时长预算”，区别Profile每次调用上限。
- 这是模型请求累计时间；不是从任务排队到研究结束的端到端耗时或服务商账单证明。外部Runner强制预留、未知用量凭证化核对仍未完成。

### Provider变更

100ms监督检查除租约/Scope/Policy/材料外，核对Provider启用、健康、配置摘要、secret_ref和updated_at。调用期间禁用、换模型或更新凭据会终止可信HTTP子进程，不接受旧输出，保留未知用量及预算。终止客户端连接不代表服务商已经停止远程推理。
